# ТЗ для разработчика: Review Hub — отзыв важнее токена

## 1. Проблема

Сейчас при открытии `/feedback/` без токена или с неизвестным/битым токеном пациент видит экран вроде **«Ссылка недействительна»**. Это тупик: человек мог перейти по укороченной ссылке, из сторис, QR или скопировать URL без token — и мы теряем отзыв.

**Принцип продукта:** токен нужен для трекинга и дожимов; **отзыв важнее токена**. Страница никогда не должна выглядеть как ошибка доступа.

## 2. Цель

1. Любой заход на Hub (с токеном или без) ведёт к полезному экрану: благодарность за отзыв + фото команды + кнопки на карты.
2. На странице с токеном добавить малозаметный способ отметить «я уже оставил отзыв на этой площадке» (без ухода на карту повторно).
3. Не ломать anti-spam лестницу и журнал там, где token есть.

## 3. Scope

| В scope | Вне scope |
|---|---|
| UX `/feedback/` и `/feedback/<token>` | Главная clinic site, IA, patient-site CSS |
| Копирайт landing / gone → marketing fallback | WhatsApp API / авто-дожимы (фаза D) |
| Кнопки «уже оставил» + события в store | Баллы/скидки за отзыв (запрещено) |
| Фото команды (существующий asset клиники) | Новая фотосъёмка |

Код: `site-raimovdental/feedback-hub/` (render, content, server, store, CSS).  
Деплой: как сейчас (`deploy-feedback-hub.sh` / grainee), не из «голого» satellite без sync.

## 4. Поведение по URL

### 4.1. `GET /feedback/` (нет токена)

**Не показывать:** «Ссылка недействительна», «персональная ссылка обязательна», пустой 404-смысл.

**Показывать (marketing fallback):**

1. Заголовок в духе: «Будем благодарны за ваш отзыв» (точный текст — в `content.mjs`, согласовать с маркетингом).
2. Короткий lead: честный отзыв помогает другим пациентам; без «поставьте 5★», без скидок/баллов.
3. **Фото команды** (использовать существующий patient-site asset, напр. team photo; `alt` без PII пациентов).
4. **Три яркие кнопки** площадок: Яндекс · 2ГИС · Google → прямые URL из конфига карт (как сейчас в Hub).
5. Опционально: WhatsApp клиники мелкой ссылкой внизу.
6. `noindex` сохранить.

Трекинг без токена: достаточно анонимных событий уровня `anon_hub_opened` / `anon_platform_clicked` (если store позволяет без token — отдельный anonymous journal или session cookie; **не** выдумывать patient_token). Если анонимный журнал сложно — минимум: кнопки работают (click-out), серверный лог клика по площадке без привязки к пациенту.

### 4.2. `GET /feedback/<unknown|expired|malformed>`

**Тот же marketing fallback**, что в §4.1.  
**Не** различать для пользователя «не существовал» vs «истёк» (без утечки существования токенов в тексте).  
HTTP: предпочтительно **200** с fallback UI (не 404 с текстом ошибки). Health/admin не менять.

### 4.3. `GET /feedback/<valid-token>`

Текущий поток CSAT 1–5★ и ветки сохраняются.

**Добавить** на экране с кнопками площадок (после оценки 4–5 и везде, где показываются кнопки карт):

Для каждой площадки, которая ещё **не** в статусе done:

- основная кнопка: «Оставить отзыв на …» (как сейчас);
- **малозаметная** вторичная: «Я уже оставил отзыв на этой карте».

Стиль вторичной: text-link / ghost / мелкий underline под основной кнопкой; не конкурировать с CTA; не выглядеть как третья крупная кнопка ряда.

По клику «уже оставил»:

1. Площадка помечается done (серая), как при `platform_clicked`, **но** событие другое: `platform_marked_done` / `already_reviewed` (не путать с кликом на карту).
2. Редирект обратно на Hub (PRG), без ухода на Яндекс/Google/2ГИС.
3. Дожимы WhatsApp для этой площадки больше не нужны (считать покрытой для лестницы).
4. Не требовать скриншот, не проверять текст отзыва.

Если все три площадки done (клики + «уже оставил») — экран «спасибо, все площадки».

## 5. Копирайт (черновик → можно править в content)

**Fallback / без токена**

- Title: «Будем благодарны за ваш отзыв»
- Lead: «Если вам был полезен визит в Expert Dental Studio — честное впечатление на карте помогает другим пациентам выбрать клинику. Это займёт пару минут.»
- Не писать: «ссылка недействительна», «только по персональной ссылке», «поставьте 5».

**Уже оставил**

- Label: «Я уже оставил отзыв на этой карте»
- После действия: площадка в состоянии «Отзыв оставлен» (тот же done-label, что сейчас).

**Footer** (сохранить смысл): оценка/отзыв не дают скидок и бонусов.

## 6. Данные и события

| Событие | Когда |
|---|---|
| `anon_hub_opened` | открыт `/feedback/` или invalid token fallback |
| `anon_platform_clicked` | клик по карте без token |
| `platform_clicked` | как сейчас, valid token → уход на карту |
| `platform_already_reviewed` | valid token, нажал «уже оставил» |
| (без изменения) `csat_scored`, recovery, opt-out | как сейчас |

Журнал admin: колонка/флаг, чем закрыта площадка — `clicked` vs `already_reviewed`.

## 7. Запреты (не нарушать)

- Нет баллов/скидок/«за отзыв получите».
- Нет «поставьте только 5».
- Нет тупикового экрана «ссылка недействительна» для пациента.
- Не трогать routes patient-site вне `/feedback/*`.
- Не показывать PII / диагнозы на fallback.

## 8. Acceptance criteria

- [ ] `https://clinic.raimovdental.com/feedback/` → **200**, текст благодарности, фото команды, 3 кнопки карт; **нет** «недействительна».
- [ ] `https://clinic.raimovdental.com/feedback/not-a-real-token` → тот же полезный UI (200), не error-dead-end.
- [ ] Valid token после 4–5★: у каждой незакрытой площадки есть малозаметная «Я уже оставил отзыв на этой карте».
- [ ] «Уже оставил» делает площадку серой без перехода на карту; в журнале отличие от click-out.
- [ ] Кнопки карт ведут на актуальные URL Яндекс / 2ГИС / Google из конфига.
- [ ] `check-feedback-hub` / smoke: нет регресса recovery и opt-out; нет reward-copy.
- [ ] Mobile: fallback и secondary-кнопки читаемы, не перекрывают CTA.

## 9. Рекомендуемый порядок работ

1. Заменить `gone` + `landing` на единый marketing fallback (copy + team photo + 3 map buttons).
2. Роуты invalid/missing token → fallback 200.
3. Добавить POST (или аналог) `already_reviewed` + UI secondary buttons.
4. Admin/journal + тесты.
5. Deploy feedback-hub на clinic, ручной smoke.
