# Система планирования и отчётности

## 1. Логика системы

```text
стратегия → утверждённый план периода → текущий статус → промежуточные отчёты → итоговый отчёт → следующий период
```

Каждый результат должен быть связан с этапом воронки:

```text
внимание → доверие → обращение → запись → визит → диагностика → план лечения → оплата → повторное лечение → рекомендация
```

## 2. Уровни планирования

### Уровень 1. Стратегия

Хранится в SSOT и определяет направления, ограничения и коммерческий канон. Не переписывается в периодных планах.

### Уровень 2. План периода

Фиксирует только согласованный объём конкретного периода. Для первого месяца действует строгий канон из 16 пунктов.

### Уровень 3. Текущий статус

`STATUS.md` показывает, что реально происходит сейчас по каждому пункту плана:

- `Не начато`;
- `В работе`;
- `Заблокировано`;
- `Выполнено`.

Статус `Выполнено` используется только при наличии материального подтверждения или проверяемого результата.

### Уровень 4. Отчёты

- промежуточный отчёт — фиксирует факты на контрольную дату;
- итоговый отчёт — закрывает период и отделяет выполненные действия от бизнес-результатов.

## 3. Структура отчёта

Каждый отчёт содержит:

1. краткое резюме для владельца;
2. период и статус;
3. что сделано по утверждённому плану;
4. подтверждения и ссылки;
5. показатели маркетинга;
6. показатели обработки и записи;
7. показатели клиники;
8. показатели репутации;
9. ограничения и блокеры;
10. следующий фокус строго в рамках утверждённого периода;
11. перечень новых материалов с ID из реестра.

## 4. Четыре уровня показателей

### Маркетинг

- просмотры;
- переходы;
- звонки;
- сообщения;
- заявки;
- источники;
- стоимость обращения, если данные доступны.

### Запись

- скорость ответа;
- конверсия обращения в запись;
- потерянные обращения;
- причины отказов;
- повторные касания.

### Клиника

- доходимость;
- консультации и диагностики;
- выданные планы лечения;
- конверсия плана в оплату;
- средний чек;
- выручка;
- внутренние направления.

### Репутация

- новые реальные отзывы;
- количество опубликованных отзывов;
- рейтинг;
- свежесть обратной связи;
- ответы клиники;
- повторные визиты и рекомендации.

Если данных нет, отчёт должен прямо указывать, что показатель ещё не собирается. Числа не придумываются.

## 5. Разделение активности и результата

| Активность | Возможный результат | Как подтвердить |
|---|---|---|
| Создана страница | рост видимости или обращений | индексация, переходы, события, заявки |
| Написан скрипт | рост конверсии в запись | сравнение диалогов и конверсии до/после |
| Получены отзывы | рост доверия | публикации, рейтинг, действия в карточке |
| Проведено обучение врачей | рост внутренних направлений | CRM/журнал направлений и доходимость |
| Настроена аналитика | появилась измеримость | заполненность источников и отчёт по воронке |

Нельзя заявлять бизнес-эффект только на основании выполненной работы.

## 6. Ответственные

| Роль | Ответственность |
|---|---|
| Валерия | текущий статус, реестр материалов, рабочие ссылки, черновик отчёта |
| Дмитрий | стратегия, итоговая редакция и передача отчёта клиенту |
| Управляющий клиникой | операционные данные, внедрение и контроль сотрудников |
| Врачи и администраторы | выполнение утверждённых регламентов и фиксация данных |
| Атабек Саидович | решения владельца и согласование медицинских формулировок |

## 7. Порядок начала нового периода

1. Получить прямое согласование состава работ.
2. Создать `periods/<period-id>/PLAN.md`.
3. Создать пустой `STATUS.md` с теми же пунктами.
4. Создать `reports/README.md`.
5. Зарегистрировать период и его клиентские страницы в реестрах.
6. Не переносить незавершённую задачу автоматически: перенос должен быть явно отражён.

## 8. Порядок обновления в течение периода

После создания материала или завершения действия:

1. обновить `STATUS.md`;
2. добавить материал в `MATERIALS_REGISTER.md`;
3. добавить URL в `LINKS_REGISTER.md`, если он есть;
4. добавить факт в ближайший промежуточный отчёт;
5. приложить подтверждение;
6. не изменять исходный `PLAN.md` задним числом.

## 9. Итоговый отчёт периода

Итоговый отчёт должен показать:

- что было запланировано;
- что выполнено полностью;
- что выполнено частично;
- что не выполнено и почему;
- какие материалы переданы;
- какие показатели изменились;
- где данных недостаточно;
- какие работы являются регулярными и продолжаются;
- что требует отдельного согласования на следующий период.

## 10. Клиентская веб-витрина

Производное представление планов и отчётов находится на `raimovdental.com/ru/valeria/`.

Источник данных веб-витрины: `site-raimovdental/work-reports/content.mjs`.

При расхождении приоритет имеют:

1. утверждённый SSOT;
2. периодный `PLAN.md`;
3. периодный `STATUS.md` и отчёты;
4. клиентская веб-витрина.

## 11. Ограничения

- Не гарантировать публикацию отзывов, рейтинг, позиции, выручку или количество лидов.
- Использовать только реальные отзывы пациентов и этичные механики.
- Не хранить пациентские данные и секреты в репозитории.
- Не добавлять задачи в первый месяц сверх утверждённых 16 пунктов.
- Cursor не использовать без прямой команды пользователя.
