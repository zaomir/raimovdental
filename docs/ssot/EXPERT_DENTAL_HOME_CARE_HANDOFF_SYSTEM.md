# Expert Dental — система домашнего ухода и handoff (Home Care Handoff)

## 0. Главный вывод

В клинике уже есть витрина средств гигиены, но пациент часто **не узнаёт** о ней и уходит покупать уход в сторонний магазин (кейс: ирригатор после виниров → Vegas). Атабек Саидович согласен внедрять рекомендации **без рекламного давления**: врач не должен «продавать бренды»; достаточно помочь тем, кто сам готов взять уход, и закрыть клиническую пользу.

Канон системы:

> **Врач назначает класс ухода → администратор выдаёт памятку и закрывает handoff → витрина тихо подтверждает наличие.**

Это не «допродажа в лоб», а **медицински уместный следующий шаг после процедуры** (как внутреннее направление и warm handoff в элитной стратегии).

Публичные claims о «магазине клиники», акциях и гарантированном ассортименте **запрещены**, пока medical review памяток, approved SKU-list и пилот не закрыты.

---

# 1. Позиция владельца (зафиксировано из переписки)

| Утверждение Атабека | Следствие в системе |
|---|---|
| Витрина уже есть | Канал 1 — зона ожидания / ресепшен; сделать **заметной без рекламы** |
| Не хочет «основательно продавать», только тем, кто сам хочет | Один мягкий оффер; после отказа — без дожима |
| «Доктор не должен быть бизнесменом» (самооценка) | Врач: **0% с SKU**; польза, не бренд |
| Готов внедрить, если предложим как | Три канала + памятки + матрица процедура→доп.→продажа + UI |

# 2. Три канала

## 2.1. Витрина (ожидание)

- Группировка **по показаниям**, не по брендам («После гигиены», «Чувствительность», «Виниры», «Брекеты»).
- Табличка: «Средства для домашнего ухода по рекомендации врача».
- Запрет: акции, «хит продаж», скидочные плакаты, голосовые объявления.
- Нормы количества: `docs/raimov/operations/expert-dental/home-care/SHOWCASE_STOCK_LIST.md` (ED-MAT-060).

## 2.2. Врач (клиническая рекомендация, ≤30 сек)

1. Что сделали / что заметили.  
2. Зачем уход **сегодня вечером**.  
3. Один **класс** средства (щётка / низкоабразивная паста / ирригатор / ёршики).  
4. Передача: «На ресепшене покажут варианты и выдадут памятку; покупать у нас не обязательно».

Поле передачи: `doctor_care` ∈ {`none`, `soft_brush`, `low_abrasive_paste`, `irrigator`, `interdental_brushes`, `ortho_brushes`, …}.

## 2.3. Администратор (скрипт + корзина + памятка)

При выборе процедуры из прайса интерфейс показывает:

1. **Скрипт** (что сказать);  
2. **Корзину ухода** (галочки, default из матрицы + отметка врача);  
3. **Памятку** — обязательная печать и выдача;  
4. **Доп. процедуру / следующий визит** (recall, эндо-2, коронка, ФДМ, ретейнер…).

Статусы: `memo_printed` · `care_offered` · `care_taken` · `care_declined` · `care_external`.

# 3. Памятка пациента

| Правило | Канон |
|---|---|
| Кто печатает | **Администратор** (врач не тратит время у кресла) |
| Сколько шаблонов | **1:1 с прайсом** — 77 памяток (`memos/by-procedure/`, ED-MAT-058) |
| Формат | A5; без брендов и цен; без гарантий результата |
| Рецепт для памяти | Обязательный перечень: уход (`care_basket`), препараты (аптека — только по назначению врача, пустые строки), следующий визит, рукописные указания |
| Gate | Medical review Атабека / назначенного врача до массовой печати |

Групповые 7 шаблонов (ED-MAT-056) — legacy/пилот; канон печати = by-procedure. Блок «Рецепт для памяти» — памятка к покупкам, не юридический рецепт.

# 4. Матрица «процедура → доп. процедура → продажа»

Для каждой позиции `PRICE_CATALOG.json`:

| Колонка | Содержание |
|---|---|
| Процедура | Услуга прайса |
| Доп. процедура | Следующий клинический шаг / запись до ухода |
| Продажа | Класс SKU: `clinic` и/или `магазин` (ориентир, не бренд-канон) |

Операционные артефакты:

- человекочитаемо: `PROCEDURE_ADDON_MATRIX.md` (ED-MAT-057);  
- машиночитаемо + UI: `HOME_CARE_MATRIX.json` (ED-MAT-059).

Примеры:

| Процедура | Доп. процедура | Продажа |
|---|---|---|
| Профгигиена лёгкая | След. гигиена ~6 мес | Мягкая щётка сегодня |
| Профгигиена тяжёлая | Этап 2 через 7–14 дн. | Щётка + паста по показанию |
| Эндо 1-е посещение | Обязательно 2-е | Щётка по ситуации |
| Эндо 2-е | Коронка | Уход после ортопедии |
| Удаление | Контроль 3–7 дн.; план замещения | День 0: без retail в лунку |
| Брекеты | Активации + гигиена 1–3 мес | Орто-ёршики, воск, ирригатор |

# 5. Мотивация персонала

| Роль | Модель | Статус |
|---|---|---|
| Врач | **0% с SKU**; учёт качества рекомендации по показанию | Канон для согласования |
| Администратор | Фикс или 5–10% от **маржи** ухода только при `memo_printed` и без дожима после отказа | После пилота 2 недели |
| Командный фонд | Опционально: часть маржи ухода → фонд админов/гигиенистов | Опция |

Запрет: % врачу за бренд; % за повторный дожим после «нет».

# 6. Склад и витрина

Источник: корзины `HOME_CARE_MATRIX` → `SHOWCASE_STOCK_LIST` (ED-MAT-060).

Пилотные нормы (классы, не бренды): **12 SKU-классов**, ~70 единиц на витрине, ~294 на складе (витрина + подсобка, 2–4 недели).

Приоритет A (всегда на витрине): мягкая щётка, ёршики/суперфлосс.

# 8. Связь с договором и открытыми вопросами

Система **поддерживает** пункты плана месяца 1 №10–11 (внутренний маркетинг / речевые маркеры) и не расширяет locked-состав 16 пунктов.

Открытые условия **retainer + success fee** и данные baseline остаются в:

- `EXPERT_DENTAL_RAIMOV_ELITE_STRATEGY.md` §17 «Решить с Атабеком Саидовичем»;  
- §23 решения встречи;  
- `RAIMOV_LEGAL_GATES.md` (юридические вопросы, статус НЕ ОТПРАВЛЕНО).

Home Care Handoff **не является** частью формулы success fee, пока отдельно не согласовано. Розница ухода учитывается отдельно от SF high-ticket.

Пакет подтверждений клиники по сайту: `research/raimov-profile/CLINIC_PENDING_PACKET.md` (C-01…C-27) — смежный, но другой контур.

# 10. Фазы внедрения

| Фаза | Содержание | Gate |
|---|---|---|
| 0 | SSOT + матрица + демо UI + черновики памяток | принято стратегически (DEC-787) |
| 1 | Medical review памяток пилота (гигиена, терапия, удаление, эндо, орто) | Атабек / клинический ревьюер |
| 2 | Approved SKU-list + закупка по ED-MAT-060 + витрина в ожидании | Клиника |
| 3 | Пилот 2 недели: гигиена → терапия → эндо; разбор KPI | Админ + гигиенист |
| 4 | Решение по % админа; расширение на орто/коронки/импланты | Атабек |
| 5 | Подключение к кассе/CRM (не демо) | Тех + клиника |

## KPI пилота (не «план продаж врача»)

- % визитов с `memo_printed`;  
- % `care_taken` | `care_declined` | `care_external` после оффера;  
- % записей `next_visit` до ухода;  
- доля врачей, передавших `doctor_care` при показании.

# 12. Статус принятия

## Принято стратегически (DEC-787)

- Три канала: витрина / врач / администратор.  
- Памятку печатает администратор; 1:1 с процедурой прайса.  
- Врач — польза и класс ухода, без брендов и без % с SKU.  
- Матрица процедура → доп. процедура → продажа обязательна для UI.  
- Розница ухода отделена от success fee до отдельного согласования.

## Открыто

- Medical review всех памяток.  
- Конкретные бренды и закупочные артикулы.  
- Финальная схема мотивации администратора.  
- Production CRM/касса.
