# SOP: три канала ухода + памятка пациента

## Цель

Закрыть уже существующий спрос пациента на домашний уход **без рекламного давления**, сохранить клиническое достоинство врача и не терять время у кресла.

Пациент уходит с:

1. понятным «что делать сегодня вечером»;
2. печатной памяткой по процедуре;
3. возможностью взять рекомендованное средство у ресепшена — **если сам хочет**.

## Принцип именования

Внутри клиники не говорить «допродажа». Говорить: **рекомендация по уходу**, **handoff**, **памятка после процедуры**.

---

# Канал 1. Витрина (зона ожидания)

## Где

Предпочтительно в **комнате отдыха / зоне ожидания** (не обязательно только у кассы). Допустима вторая тихая полка у ресепшена.

## Как оформить

- Группировка **по показаниям**, не по брендам: «После гигиены», «Чувствительность / тонкая эмаль», «Виниры», «Брекеты / элайнеры», «После удаления».
- Табличка: «Средства для домашнего ухода по рекомендации врача».
- Бренд — мелким шрифтом на ценнике или на обороте карточки; на лицевой стороне — **польза** (мягкая щетина, низкая абразивность, межзубной уход).
- Запрещены: акции, «хит продаж», скидочные плакаты, голосовые объявления.

## KPI витрины

Не «конверсия витрины», а: доля пациентов, которые **знают**, что уход можно взять в клинике (короткий опрос 1×/неделя или поле «узнал о витрине»).

---

# Канал 2. Врач (клиническая рекомендация)

## Роль

Врач **назначает класс ухода**, не продаёт SKU и не называет цену.

## Правило 30 секунд

1. Что заметил / что сделали сегодня.  
2. Зачем уход **сегодня вечером** (не «когда-нибудь»).  
3. Один класс средства (щётка / низкоабразивная паста / ирригатор / ёршики).  
4. Передача: «На ресепшене покажут варианты; если удобнее купить сами — тоже нормально. Администратор выдаст памятку.»

## Примеры (польза, не бренд)

| Ситуация | Формулировка врача |
|---|---|
| После профгигиены | «Сегодня вечером чистите уже новой мягкой щёткой — старая снимает эффект чистки.» |
| Тонкая / чувствительная эмаль | «Нужна низкоабразивная паста, чтобы не стирать эмаль дальше.» |
| Виниры / ортопедия | «Для сохранения результата важен бережный межзубной уход — обычно ирригатор или специальные ёршики.» |
| Ортодонтия | «Вокруг замков налёт остаётся — нужны ёршики / ирригатор, иначе риск пятнен и воспаления.» |

## Чего врач не делает

- не перечисляет бренды и цены;
- не говорит «акция», «все берут», «без этого лечение бессмысленно»;
- не заполняет корзину и не печатает памятку (экономия времени у кресла).

## Передача админу

Устно или поле в карте / CRM:

`home_care: soft_brush | low_abrasive_paste | irrigator | ortho_brushes | none`

# Канал 3. Администратор (скрипт + корзина + памятка)

## Когда срабатывает

Как только админ **выбрал / ввёл процедуру** в интерфейсе (или видит её в чеке перед оплатой), система показывает блок handoff (см. матрицу).

## Обязательный блок в интерфейсе

1. **Скрипт** — 1–2 фразы, что сказать.  
2. **Корзина ухода** — позиции с галочками (можно снять).  
3. **Памятка** — кнопка «Печать памятки» (обязательный шаг перед закрытием визита).  
4. **Статусы:** `memo_printed` · `care_offered` · `care_taken` · `care_declined` · `care_external`.

## Правило давления

- Один мягкий оффер.  
- Отказ фиксируется → **без повторного дожима**.  
- Если врач отметил `home_care: none` и пациент не спрашивал — админ **не** инициирует корзину; памятку всё равно выдаёт.

## Скрипт выдачи памятки (единый каркас)

> «После [процедура] у нас есть короткая памятка — что делать сегодня вечером и в ближайшие дни. Внизу — список «что купить / взять», как памятка к рецепту врача: отметьте галочками то, что доктор рекомендовал. Если удобно взять средства здесь — покажу; если нет — ориентиры уже в памятке.»

## Порядок у кассы

1. Печать памятки по процедуре (с блоком «Рецепт для памяти»).  
2. Выдать памятку в руки; при необходимости отметить галочки/вписать препараты по устной схеме врача.  
3. Предложить позиции из матрицы (с учётом отметки врача).  
4. Оплата лечения ± уход.  
5. Записать следующий визит; зафиксировать статусы.

# Памятка пациента

## Кто предлагает

| Роль | Действие |
|---|---|
| **Администратор** | **Основной исполнитель:** печатает и выдаёт после **каждой** завершённой процедуры / визита по матрице. |
| **Врач** | Может устно сказать «памятку дадут на ресепшене»; не обязан печатать. |
| **Гигиенист** | Как врач: рекомендация класса ухода; печать — админ. |

## Правило «своя памятка на процедуру»

Для **каждой позиции прайса** — свой файл в `memos/by-procedure/` (индекс: `INDEX.json` / `INDEX.md`). Админ печатает memo_id выбранной услуги. Если за визит несколько процедур — по приоритету клинической срочности (удаление → эндо → хирургия/имплант → …) или две памятки, если обе критичны.

Групповые шаблоны `memo-hygiene` и т.п. — только запасной пилот; канон печати = by-procedure.

## Формат

- A5, одна сторона или оборот «когда звонить».  
- Обязательный блок **«Рецепт для памяти — что купить / взять»**: уход (из матрицы), препараты (аптека, только по назначению), следующий визит, рукописные указания.  
- Без брендов и цен.  
- Без гарантий результата.  
- Не заменяет очный рецепт/схему врача — только памятка для пациента.  
- Язык: простой русский; при необходимости клиника добавляет кыргызский позже.  
- Медицинский gate: до массовой печати — утверждение Атабека / назначенного врача.

## Поле учёта

`memo_id` + `memo_printed: yes/no` + кто выдал (админ).

# Мотивация (% от продажи)

## Рекомендуемая модель (к согласованию с Атабеком)

| Роль | Модель | Обоснование |
|---|---|---|
| **Врач** | **0% с SKU** | Сохраняет доверие; совпадает с «доктор не продавец». Учёт качества: доля визитов с клинически уместной рекомендацией класса ухода. |
| **Администратор** | Фикс **или** 5–10% от **маржи** ухода в чеке, только при `memo_printed` + без дожима после отказа | Мотивирует закрытие handoff, не «впаривание». |
| **Командный фонд (опция)** | Часть маржи ухода → ежемесячный фонд админов/гигиенистов | Избегает личной привязки врача к бренду. |

## Запреты по мотивации

- % врачу за конкретный бренд или SKU;  
- % за повторное предложение после явного «нет»;  
- баллы/скидки пациенту «за покупку на витрине» без отдельного clinic rule.

Пилот **2 недели** без % → затем решение по цифрам.

# Запреты (все каналы)

- Диагноз и обещание результата в скриптах админа.  
- Рекламный тон у кресла и у кассы.  
- Подмена памятки прайсом или каталогом брендов.  
- Хранение ПДн в Git / в текстах памяток.

---

# Внедрение (пилот)

1. Утвердить approved list SKU (6–10 позиций) и матрицу.  
2. Медицинский review памяток пилота: гигиена, терапия (пломба), удаление, виниры/орто.  
3. Разместить витрину в ожидании.  
4. Обучить админов: печать → выдача → один оффер.  
5. Поля CRM / журнал 2 недели.  
6. Разбор: выдано памяток / взяли уход / отказ / купили вне клиники.

## Связь с планом месяца 1

Поддерживает пункты **10** (работа с терапевтами и гигиенистами) и **11** (речевые маркеры и передача), не добавляя 17-й пункт в locked-план.
